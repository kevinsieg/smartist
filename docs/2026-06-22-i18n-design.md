# i18n — three-language support (EN default, FR, DE)

Date: 2026-06-22
Status: Design approved, pending spec review

## Goal

Serve the whole app in English (default), French, and German. Detect the
visitor's language on first visit from the browser; remember the choice
thereafter. Let users pick a language (flag selector) in `/profile` and from a
global switcher. Supporting three languages must not increase page weight or
cause a flash of untranslated content.

## Decisions

| Question | Decision |
|----------|----------|
| Scope | Whole app, **except `stage.html`** (stays English — it has no `common.js`). |
| First-visit detection | Browser language (`navigator.language`), client-side only. |
| Persistence | `localStorage` only — no DB/API/schema change. |
| Switcher location | `/profile` selector **and** a global switcher in the injected footer (works logged-out). |
| Switch behaviour | Store choice, then **reload the page once**. |
| Out of scope (YAGNI) | Per-user DB persistence, geo-IP detection, `Intl` date/number localization, translating emails / PDF export, `stage.html`. |

## Architecture

### Locale files
- `app/i18n/en.json`, `app/i18n/fr.json`, `app/i18n/de.json`.
- Flat keys grouped by area: `nav.songs`, `profile.email`, `common.save`, etc.
- **English is the source of truth.** French and German generated by Claude, to
  be reviewed by a native speaker before merge.
- All three files must contain the **same key set** (enforced by a parity test).
- Served as static CDN assets with a `?v=<n>` cache-bust query, like the
  existing CSS/JS versioning.

### Standalone helper: `app/js/i18n.js`
Loaded in the `<head>` of **every translated page**, before any other script,
including the six public pages that do **not** use `common.js` (landing,
signup, demo, onboarding, workspaces, impressum). `common.js` *consumes* this
module (`window.i18n` / `window.t`); it does not own the i18n logic. Keeping it
standalone also avoids growing the already-large `common.js`.

The file is **UMD-style**: its pure functions are exported via
`module.exports` for Node unit tests, and the browser glue runs only when
`typeof document !== 'undefined'`, so requiring it in Node has no side effects.

Pure functions (Node-testable, no globals):
- `resolveLocale(stored, navLangs, supported, def)` — precedence logic.
- `translate(dict, key, vars)` — lookup + `{var}` interpolation + key fallback.
- `readCachedDict(raw, version)` — parse a localStorage cache entry, returning
  the dictionary only if its version matches.

Browser glue, no dependencies:

- `getLocale()` — returns the active locale using precedence:
  `localStorage['smartist_lang']` → `navigator.language` matched to `en|fr|de`
  → `'en'`.
- `t(key, vars)` — looks the key up in the loaded dictionary; interpolates
  `{var}` placeholders from `vars`; falls back to the key string (and warns in
  dev) when missing.
- `applyTranslations(root)` — walks `root` for:
  - `[data-i18n="key"]` → sets `textContent` to `t(key)`.
  - `[data-i18n-attr="placeholder:key;aria-label:key2"]` → sets each named
    attribute to `t(key)`.
- `getLocale()`, `t(key, vars)`, `applyTranslations(root)`.
- `setLocale(locale)` — stores the choice in `localStorage`, then reloads.
- `window.i18n.ready` — a Promise that resolves once the dictionary is loaded
  and `applyTranslations(document)` has run.
- `mountLangSwitcher(target)` — renders the flag switcher into `target`.

### Dictionary loading (performance + no-flash)
- **Only one locale dictionary is ever loaded.** Three languages add no page
  weight.
- **EN (default):** loads `en.json` like any other locale (one small file,
  then localStorage-cached). This is required because JS-generated strings call
  `t()` and have no inline English fallback — an empty EN dict would make `t()`
  and `applyTranslations` emit raw keys. No DOM hide for EN: inline English
  shows until `applyTranslations` runs (after the dict loads) and sets the same
  English, so there is no flash. *(Correction to the original "EN does no
  network" plan — that assumption only held for static HTML, not JS strings.)*
- **Dict primed synchronously** from the localStorage cache at head-load for
  every locale, so `t()` is correct before page scripts run on repeat visits.
  The two JS entry points (`initPage` in `common.js`, `home.init`) await
  `window.i18n.ready` to cover the first-visit cache-miss case.
- **Non-EN:** `i18n.js` (in `<head>`) sets `documentElement.style.opacity = 0`
  immediately, then on `DOMContentLoaded` runs `applyTranslations(document)` over
  the final DOM (including the shell `common.js` injected during body parse) and
  resolves `window.i18n.ready`, which restores opacity. This single hide/apply
  pass prevents any flash for both cached and cold dictionaries.
- **Caching:** the dictionary is cached in `localStorage`
  (`smartist_i18n_<locale>`, value `{v, dict}`); `readCachedDict` returns it only
  when `v` matches the current `I18N_VERSION`. A cache miss triggers one small
  JSON `fetch`. Repeat non-EN visits do no network.
- **`common.js` fade-in is gated on `window.i18n.ready`** so its existing
  header-fade never reveals untranslated content. For EN, `ready` resolves
  immediately, preserving today's behaviour.

## Markup conventions

- **Static HTML text** → `data-i18n="key"`, with the current English text left
  inline as the default/fallback.
  ```html
  <label data-i18n="profile.email">Email</label>
  ```
- **Attributes** (placeholder, aria-label, title, alt) →
  `data-i18n-attr="placeholder:profile.pwNew"`.
- **JS-generated strings** (innerHTML, toasts, validation messages, the injected
  nav/footer) → `t('key')`.

### Shell handling
`injectShell()` builds the nav and footer with `data-i18n` keys and English text
inline. It does **not** translate them itself — the single
`applyTranslations(document)` pass in `i18n.js` (on `DOMContentLoaded`, after the
shell exists) covers the shell and the page body together.

## Language switcher UI

- **Footer:** compact flag dropdown rendered by `mountLangSwitcher()`. On
  `common.js` pages it mounts into the injected footer; on the six non-common
  public pages it mounts into a `[data-lang-switcher]` hook placed in their
  existing footer. Three small **inline SVG flags** (EN/GB, FR, DE) with endonym
  labels (English / Français / Deutsch — endonyms are not translated) — no new
  dependency, crisp cross-platform.
- **/profile:** a labelled flag selector row (three flag buttons) calling
  `setLocale()`.

## Rollout (phased — whole-app extraction is large)

1. **Phase 1 — infrastructure.** `app/js/i18n.js` (pure functions + browser
   glue + switcher); `en/fr/de.json` skeletons; `<head>` script tag on the
   pilot pages; `common.js` consuming `window.i18n` and gating its fade on
   `window.i18n.ready`; profile selector. Verified on the shell (nav + footer)
   and `/profile`.
2. **Phase 2+ — page-by-page extraction.** Each page (its HTML **and** its JS
   together) gets the `<head>` script tag, `data-i18n` / `t()` markup, and keys
   added to all three locale files. Each page is independently verifiable.

**Translated page set (`stage.html` and the `api-docs.html` developer
reference excluded):** common.js pages — contact, dashboard, gigs, hub, index,
organizers, pro-import, profile, setlist-history, setlist, settings, songs,
touring, venues; non-common pages — landing, signup, demo, onboarding,
workspaces, impressum.

## Testing

- **Unit (`tests/unit.js`, runs in CI):**
  - `getLocale()` precedence: stored locale wins; else browser language maps to a
    supported locale; else `en`. Includes unsupported-browser-language → `en`.
  - `translate()`: returns the translated string, interpolates `{var}`, and
    falls back to the key when missing.
  - `readCachedDict()`: returns the dict on a version match, `null` on mismatch
    or malformed JSON.
  - Locale-file **key parity**: `en`, `fr`, `de` expose an identical key set.
  - The pure functions are exported from `app/js/i18n.js` via `module.exports`
    and required directly in Node (browser glue is skipped when `document` is
    undefined), so there is a single source of truth — no copied logic.
- **Manual / visual:** switch each language on key pages; confirm no flash,
  persistence across reload and SPA navigation, and that `<html lang>` updates.
